# Plan: :Otherscape schemas

## Overview

| Field      | Value                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| **Goal**   | Fill the empty `otherscape` game with the six targets the books actually publish as repeatable fiches    |
| **Source** | The discovery brief "Schémas :Otherscape pour schema-in-the-mist", refined in conversation on 2026-09-07 |

`GAMES.otherscape` is already declared in `src/zod/constants.ts` and the README names :Otherscape in its first line, but no target has ever pointed at it, so `schemas/otherscape/` and `examples/otherscape/` do not exist — and, as phase 1 shows, the generator cannot create them. This plan closes that gap for everything the three books publish as a catalogable record, and stops there: `themebook`, `job` and `district` are named out of scope below rather than silently dropped.

| 3   | Ship the `power-set` target                       | [`phase-3.md`](./phase-3.md) |
| 4   | Ship the `theme-kit` target                       | [`phase-4.md`](./phase-4.md) |
| 5   | Ship the `theme` target                           | [`phase-5.md`](./phase-5.md) |
| 6   | Ship the `character-trope` target                 | [`phase-6.md`](./phase-6.md) |
| 7   | Ship the `loadout-item` target                    | [`phase-7.md`](./phase-7.md) |

Phase 1 is not optional preparation, it is a blocker: `tools/gen-schemas.ts` cannot create `schemas/otherscape/`, so the first target aimed at a game with no existing directory crashes on `npm run gen`. It comes first because nothing after it can pass its own criteria otherwise, and it stands alone because it is an upstream defect that deserves a cherry-pickable commit.

The rest of the order is load-bearing twice, not tidy. Phase 2 precedes phase 3 because a Power Set is a Challenge fragment: its Specials and its Threats/Consequences are the shapes phase 2 defines, and writing them second means copying a decided shape rather than inventing a parallel one. Phase 4 precedes phase 5 because the theme vocabulary — `theme_type`, `category`, `title_tag`, `quest` — is settled on the kit, and the played theme adds only the two tracks on top. Phases 6 and 7 depend on nothing and on each other not at all; they come last because they are the cheapest, not because anything waits on them.

Phase 2 also carries the question the plan's scope rests on: whether an :Otherscape record can reuse the Legend in the Mist shapes at all. If it cannot, that is known after one target instead of six.

## Decisions

| Decision                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No union at the root of any target, anywhere in this plan                                                     | The README's third announced use is editor autocomplete driven by a `$schema` hint. A root `oneOf` is precisely what editor JSON Schema support handles least evenly, so the shape that serves the announced use is a flat, closed object per file. This is the criterion the whole plan applies, not a one-off ruling about `quest`.                                                                                       |
| The theme's driving question is **one** `quest` field, with a required `theme_type` beside it                  | Follows from the row above. The three names — Identity for Self, Ritual for Mythos, Itch for Noise, each printed as its own label inside the kit blocks — live in the field's `description`, not in three mutually exclusive properties. The cost is real and accepted: the field name no longer says which of the three it holds, so a consumer reads `theme_type` to know.                                                |
| `category` holds the themebook, as a **free string**, spelled exactly as on `litm/theme-kit` and `litm/story-theme` | Both existing files chose a free string over an enum "so that homebrew themebooks remain expressible", and already note that the identical spelling makes the value copy across unchanged. Closing the set for :Otherscape would break that symmetry for no gain, and each setting book keeps adding themebooks.                                                                                                            |
| The played theme is named `theme`, not `story-theme`                                                          | `litm/story-theme` describes "one of the themes a Hero is built from" — the same object — but "Story Theme" is Legend in the Mist vocabulary, and :Otherscape says "theme" throughout. The folders already namespace the two, so each game keeps its own word.                                                                                                                                                              |
| Crew Theme Kits are **not** a separate target                                                                 | They are printed with the identical anatomy: power tags, weakness tags, an Identity. `theme_type` gains a fourth value, `crew`. A second target for the same shape would double the maintenance and split the catalog for nothing.                                                                                                                                                                                          |
| `power-set` is its own target, not a sub-schema of `challenge`                                                | The books publish Power Sets as standalone, catalogable entries that graft onto *any* Challenge. A tool wants one file per Power Set, addressable by `$schema` — the same reasoning that gives every other fiche its own target.                                                                                                                                                                                            |
| No `rating` on an :Otherscape Challenge                                                                       | Measured, not assumed: "rating" occurs twice in the Metro Core Book and never as a statistic. `litm/challenge` and `com/danger` both carry one; inventing a third would describe something no producer can emit.                                                                                                                                                                                                            |
| No `level`, no `milestone` on an :Otherscape theme                                                            | :Otherscape has no theme tiers — nothing corresponds to origin / adventure / greatness — and no milestone track. Same reasoning as the row above, and the same reasoning that already kept `level` off `litm/theme-kit`.                                                                                                                                                                                                    |
| `improve` / `abandon` become `upgrade` / `decay`                                                              | The books name the two three-box tracks Upgrade and Decay, which is exactly what `litm/story-theme`'s `improve` / `abandon` count. Keeping the Legend in the Mist spelling would make the field name say something the :Otherscape sheet never says.                                                                                                                                                                        |
| `improvements` has no counterpart on the :Otherscape `theme-kit`                                              | Verified on the Affiliation themebook: Theme Specials are printed on the **themebook**, not on the theme kit. Since `themebook` is out of scope here, they have nowhere to land in this plan, and inventing a kit-level list would misplace them.                                                                                                                                                                            |
| A polar Limit is one `name` carrying both poles separated by `/`, plus an `is_polar` flag                      | This is how the books print it: `catch/outrun:3`, `catch/escape:3`. Two pole fields would nest where the printed form is flat, and flat is what survives the TOML encoding and the autocomplete use intact.                                                                                                                                                                                                                 |
| `scale` is an optional integer on `challenge`                                                                 | Scale is a property of an entity (`a jotunn Challenge (Scale 3)`), not only an effect applied during play. Optional because published profiles print no Scale line unless the Challenge is larger than a person; absent means Scale 0, which is also the PC value.                                                                                                                                                          |
| `PublicationTypeEnum` and `MetaSchema` are duplicated in each of the six files, again                          | All five existing targets define their own. Factoring them out is a repo-wide change already deferred on issue #2, and doing it here would turn six new targets into a refactor of five old ones.                                                                                                                                                                                                                           |
| Only the Street Catalog's *specific items* become `loadout-item`; the per-rubric *general items* blocks are deferred | A specific item is a record a tool instantiates: name, description, feature tags, a weakness tag. A general-items block is three lists of suggestion words attached to a rubric — closer to a lookup table than to a fiche, and it serves none of the README's three uses well.                                                                                                                                              |
| `tools/gen-schemas.ts` is fixed before any target is added                                                       | Measured: `path.dirname("schemas/otherscape")` returns `"schemas"`, so the generator creates the parent and never the game directory, and `writeFileSync` fails with ENOENT. It has stayed invisible because both existing game directories are already tracked by git. It is a defect in the upstream tool rather than anything :Otherscape adds, so it gets its own phase and its own commit, cherry-pickable into a pull request against `4rtamis/schema-in-the-mist`. |
| The :Otherscape `theme-kit` has a `title_tag` and **no** `name`                                                   | The printed block is a `THEMEBOOK THEMETYPE` header, then the first power tag alone on its line: `AFFILIATION SELF` / `CORPORATE CITIZENSHIP`. Two kits share that header and are told apart only by that tag, so the title tag *is* the kit's name. `litm/theme-kit` calls the same slot `name` and maps it onto `story-theme.title_tag`; here both ends are spelled `title_tag`, so a kit and the theme built from it line up with no mapping at all. Carrying both fields would be one value under two names with no rule saying which wins. |
| A Character Trope references kits as `{ title_tag, category }`, for its imposed three **and** its `Choose One` three | Both blocks are printed in the identical form — `Chipped Weapon Mastery (AUGMENTATION)`, `Corporate Citizenship (AFFILIATION)` — so the second is three more kit references, not prose alternatives. The field names match `otherscape/theme-kit`'s own, which is what makes the pair a lookup key rather than a fresh vocabulary. |
| Examples are invented, not transcribed from the books                                                          | Every existing example does this — "Lantern, Warden of the Wilds", "The Hedge Witch" — and each carries `publication_type: "homebrew"` for that reason. It also keeps published Son of Oak material out of the repository.                                                                                                                                                                                                   |
| `themebook`, `job` and `district` are out of scope                                                             | Structurally open rather than transcribable. A Job in particular does not map onto `litm/journey`: its per-type `COMPLICATIONS` are Escalate-the-Situation consequences, not a vignette's own consequence list, and equating the two would encode a false correspondence. Each deserves its own design discussion, per `CONTRIBUTING.md` step 2.                                                                              |
