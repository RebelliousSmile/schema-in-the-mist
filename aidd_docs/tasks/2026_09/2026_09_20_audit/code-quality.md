# Codebase Audit: schema-in-the-mist / code-quality

Le code est propre à la lecture — nommage clair, descriptions partout, aucun raccourci de typage, aucune trace de débogage. Vérifié sain :

- **Les descriptions sont systématiques et utiles**, pas décoratives : chaque champ publié porte un `description` et la plupart des `examples`, tirés des livres. Certaines expliquent un choix de modélisation plutôt que le champ lui-même — par exemple `src/zod/otherscape/challenge.ts:46`, qui justifie de garder une Limite polaire en une seule chaîne « because that is how the books print it and how it survives the TOML encoding intact ». C'est de la documentation de décision au bon endroit.
- **La séparation `src` / `tools` est nette** : `src` ne fait **aucune** entrée-sortie, `tools` porte tout le système de fichiers et les processus fils. Aucun fichier de `src` ne lit le disque.
- **La gestion d'erreur est ciblée, pas défensive** : 3 `catch` seulement sur tout le dépôt, dont un seul dans `src` (`codecs/source.ts:149`), qui filtre exactement une classe d'erreur Zod — les clés inconnues — et **relance** tout le reste (`:153`). Un `catch` qui avale serait le défaut ; celui-là discrimine.
- **Les tailles de fichier restent lisibles** : le plus gros fichier source fait 423 lignes (`src/zod/city-of-mist/theme-kit.ts`), le plus gros outil 177 (`tools/validate-handbook-packs.ts`). Aucun fichier fourre-tout.
- **Le ratio source/outillage est sain** : 4 210 lignes de `src` pour 865 lignes de `tools`, soit 4,87 — le dépôt est majoritairement du produit, pas de la machinerie.

## Top actions

1. **Extraire `src/zod/common/`** (`src/zod/city-of-mist/danger.ts:153`) : effort `M`. C'est 1 187 lignes de moins à maintenir, et surtout le seul moyen d'empêcher la prochaine divergence entre 14 copies dont 14 diffèrent déjà.
2. **Corriger le résidu « Challenge's origin »** (`src/zod/city-of-mist/danger.ts:153`) : effort `S`, à faire dans le même mouvement que l'extraction pour ne pas figer l'erreur dans la couche commune.
3. **Poser Prettier et un `typecheck` réellement branché** (`package.json:12`) : effort `S`, et cela ferait remonter les trois `any` de `tools/` par l'outil plutôt que par un audit.
