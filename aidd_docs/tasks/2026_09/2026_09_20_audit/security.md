# Codebase Audit: schema-in-the-mist / security

Aucun secret, aucune surface réseau, aucune entrée-sortie dans la bibliothèque publiée : la surface d'attaque réelle de ce dépôt est son intégration continue et son harnais. Deux points s'y relâchent — une exécution de commande construite depuis un fichier de données, sans contrôle de confinement et repassée par `cmd.exe` sous Windows, et un workflow sans déclaration de permissions. S'y ajoute une fuite d'information mineure mais publique.

Vérifié sain :

- **Aucun secret dans le dépôt** : aucune clé, aucun jeton, aucun identifiant. Les workflows n'utilisent que le `GITHUB_TOKEN` fourni par la plateforme.
- **La bibliothèque publiée n'a aucune surface d'attaque à l'exécution** : `src` ne lit pas le disque, n'ouvre pas de réseau, n'exécute pas de processus. Un consommateur qui importe ce paquet importe des schémas de validation et deux codecs, rien qui puisse être détourné.
- **La validation d'entrée est le produit même du dépôt, et elle est fermée** : les schémas générés portent `additionalProperties: false` — vérifié sur `strictObject` côté sources — donc une donnée qui apporte des clés inattendues est rejetée plutôt que silencieusement acceptée. C'est la bonne posture pour un schéma consommé par des outils tiers.
- **Le descripteur inter-outils est versionné et asserté** : `tools/validate-packs.ts:16-17` refuse un `providerVersion` autre que 1 et exige l'égalité `contractVersion === CONTRACT_VERSION`. Un descripteur d'une autre génération ne passe pas en silence.
- **Le harnais refuse le vert vide** : `tools/validate-packs.ts:37` porte `assert.ok(validated > 0)` avec le commentaire « A run that matched no manifest proves nothing, so it must not exit green. » Un chemin de manifeste qui ne correspond à rien fait échouer la vérification au lieu de la passer.
- **Le confinement de chemin existe là où le corpus est lu** : `tools/validate-contract.ts` asserte que chaque fichier de cas reste sous la racine (« Unsafe corpus path ») avant de l'ouvrir. La mécanique est donc connue du dépôt — elle manque seulement dans `validate-packs.ts`.
- **La chaîne de dépendances entrante est courte et verrouillée** : `package-lock.json` suivi, `npm ci` en intégration, aucune dépendance tirée d'un dépôt git ou d'une URL, aucun script `postinstall` maison.

## Top actions

2. **Déclarer `permissions: { contents: read }` dans `ci.yml`** (`.github/workflows/ci.yml:1`) : effort `S`, aucun effet de bord.
3. **Neutraliser le chemin absolu publié** (`schemas/otherscape/design/design-system.md:10`) : effort `S`.
